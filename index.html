Lo más interesante

Cinco ideas clave del proyecto

El proyecto combina IA, verificación de URLs y automatización para no depender de un único mecanismo de defensa.

Análisis dual

Gemini + local

Si Gemini falla por timeout o cuota, el sistema sigue con reglas heurísticas para mantener la respuesta activa.

Protección

10 req/min

El backend usa slowapi para limitar solicitudes y proteger tanto el servicio como la cuota de Gemini.

Detección

Homoglyphs

Detecta dominios parecidos a marcas reales con distancia de Levenshtein, como paypa1 o go0gle.

Stack técnico y operación

PishShield combina Chrome Extension MV3, FastAPI, Gemini 2.5 Flash, MCP y Docker Compose en un flujo simple de entender y ejecutar.

1. Chrome Extension MV3

Analiza Gmail automáticamente cada 60 segundos, actualiza el badge y dispara notificaciones cuando detecta riesgo.

2. FastAPI Backend

Recibe el correo, ejecuta el análisis y aplica rate limiting para proteger el servicio y la cuota de la API.

3. Gemini + MCP

Gemini 2.5 Flash analiza el contenido y MCP verifica URLs con Google Safe Browsing en tiempo real.

Análisis dual con fallback local

PishShield no depende solo de la IA. Primero intenta clasificar el correo con Gemini 2.5 Flash y, si hay un error, cae a un análisis local con reglas heurísticas.

  • Prompt en español y salida estructurada

    Gemini devuelve verdict, confidence, reason e indicators para que el análisis sea claro y reutilizable.

  • Verificación de URLs con MCP

    El servidor MCP consulta Safe Browsing y devuelve un resultado seguro incluso cuando el servicio no responde.

  • Homoglyphs y automatización

    Detecta dominios parecidos con Levenshtein, actualiza badge y avisa con notificaciones si la confianza supera 80%.
